# DEVPLAN-v0.19:规划智能加深 — 让 youkai 会"想",而不只是会"做"

> 交付对象:实现者(DeepSeek)。配 ADR-002(planner 只提议)、ADR-006(点头)、v0.17(排序)、v0.18(多步链)读。
> 目标:把规划从"会排序 + 一条 IDOR 链"做深成"会从证据推理、多种链型、会复盘结果想下一步、把'为什么'讲给人听"。
> **智能化是体验核心**:一个会解释自己在想什么的 agent,比要你手把手点的工具好用一个量级。
> 铁律不变:不新增任何打击动作,LLM 只提议,档 2 停人前,组链≠自动执行,candidate≠verified。

## 0. 现状(在什么之上加深)

- 排序(v0.17 `order.go`):可解释打分,有了,但维度少(证据完整度/价值/成本/trace 覆盖)。
- 多步链(v0.18 `chain.go`):只有**一条** IDOR 链,且只认第一个 BOLA pair。
- 对话卡片(`planner/chat.go`):scope_draft/mandate_draft/plan/note,单点提案为主。
- **缺口**:链型单一;不会"看了结果再想下一步";给人的是"做什么"的清单,不是"为什么这么走"的思路。

## 0.5 不可动摇(继承,逐条适用)

- LLM 只提议类型化 intent/卡片;放行、批准、升 verified 归闸门与人;**prompt 只喂归一 fact/trace/假设摘要,绝不含目标响应正文**(防注入)。
- 任何档 2 步仍停人前(ADR-006);组出的链/推理出的下一步**不等于自动执行**,每个档 2 节点单独点头。
- 推理全程可回放:planner 调用(含它看到的证据、产出的链/推理)落 `planner_calls`;确定性兜底在(无 LLM 也能规划)。
- 不新增打击能力:v0.19 只改"怎么选路、怎么解释",能提议的仍是 v0.1~v0.18 那些受闸能力。

## 1. 多链型组装 `internal/engine/chain.go`(P0)

**目标**:从一条 IDOR 链扩到一个**链型库**,每种链都是"白盒假设/已有 fact + 前置条件 → 有依赖的多步序列",每步仍各自过闸。

**新增链型(都复用现有受闸能力,只是编排)**:
- **BFLA 越权链**:角色差异假设 + 多身份 → provision(档2)→ role_matrix(档1)→ 低权可达升 candidate。
- **认证弱点链**:JWT/OAuth 配置弱点(v0.15)+ 会话探针 → 组"配置→会话固定→越权"的递进验证。
- **SSRF 确认链**:白盒 ssrf 假设 → canary 探针(档2,v0.14)→ 触达升 candidate(双证据)。
- **二进制链**:binflow 假设(v0.18)→ 标注可利用面 → 交人产 PoC 文本(Verdex 档2)。
- 覆盖所有现有 pair,不只第一个;同类链去重(不重复造)。

**实现要点**:链型用一个声明式表(前置条件 + 步骤模板 + 依赖),引擎遍历可组装的链;每条链每步仍 `gate.Classify` 定档、tier2 park。

**验收**:BFLA/认证/SSRF 链各能在对应证据齐备时组出;多个 pair 都能组链;档 2 步仍 park 逐个点头;同类不重复;链血缘可查。

## 2. 结果复盘:看了再想下一步 `internal/engine/reflect.go`(P1,"会想"的核心)

**目标**:一步执行完,引擎不只"回灌 fact + 派下一条规则",而是**综合新结果 + 全局证据,推断最该走的下一步**,并说明理由。

**要点**:
- 每步完成后产一个"复盘":新 fact 确认/推翻了哪条假设?解锁了哪条链?让哪条候选更可信?
- 据此**调整后续排序/组链**(新证据让某条链从"不值得"变"值得")。
- 复盘结论写进探索图(可审计),并可喂给下一轮 planner。
- 仍是**提议**:复盘推出的下一步若是档 2,照样 park 等人。
- **诚实**:结果是"没命中/无法判定"时,复盘如实说"这条线索未被证实",不硬找理由续命(呼应反致盲的诚实纪律)。

**验收**:probe 命中 git 泄露后,复盘把相关链提权重;探测没命中时复盘标假设 unconfirmed 不硬续；复盘结论落图可回放;档 2 仍 park。

## 3. "为什么"讲给人听 `internal/planner/chat.go` + `web/chat.js`(P1,体验)

**目标**:对话里 AI 不只给"做什么"的卡片,而是先给**一段思路**:我看到哪些证据 → 推断什么 → 所以建议这条链/这一步 → 它会停在哪等你。

**要点**:
- `plan` 卡片升级成**带推理的提案**:`reasoning`(从哪些 fact 推来)+ `chain`(多步+依赖)+ `stops_at`(哪步需要你点头)。
- 操作员读的是"思路 + 计划",不是裸命令清单;可整体看、逐步批。
- schema 仍封闭:无 approve/改 scope/升 verified 卡片(v0.11/12 红线);reasoning 只引用归一证据,不含目标正文。
- 顶部状态把"我现在在想什么/在等你什么"讲清楚(如"我认为 /orders 可能越权,正等你批准两个测试身份登录")。

**验收**:对话给出"证据→推断→计划→停在哪"的成体系提案;schema 无越权卡片;prompt 无目标正文;逐步点头;可回放。

## 4. 排序维度加深 `internal/engine/order.go`(P2)

**目标**:打分维度更丰富但仍可解释:加"链上关键步优先""新证据新鲜度""同类已验证则降重复探测",每点仍有命名理由。

**验收**:排序理由可读可争论;同输入可复现;仍是排序不是放行。

## 5. 规划质量 bench(P2,补 v0.17 没做的)

- bench 加"规划质量":同靶场到达一条 verified 用几步/几请求/几次点头;多链型场景下的组链正确率。只本机靶场,不外推。

**验收**:bench 出规划效率指标;越界=0;不因追求少步数跳过档 2 点头。

## 落地顺序

1. 模块一(多链型)+ 模块二(结果复盘)—— "会想"的核心,先做。
2. 模块三(对话讲"为什么")—— 体验,紧随。
3. 模块四(排序加深)、模块五(规划 bench)。

**每步验收锚点**:LLM 只提议、放行归人;多链型每步过闸、tier2 park;复盘诚实不硬续、结论落图可回放;
对话给思路不含目标正文、schema 无越权卡片;组链≠自动执行;candidate≠verified;`go test ./...` 全绿;门禁仍过。

## 一句话

让 youkai 从"按清单挨个测、要你手把手点",变成"看着证据跟你说:我觉得这里可疑、打算这么验、会停在这等你点头" ——
聪明长在"想清楚下一步"和"把想法讲明白"上,绝不长在"自己越过那道该停的闸"上。
