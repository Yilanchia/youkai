# DEVPLAN-v0.20:打通"说一声就真渗"的闭环 —— 对话直接开工(修可用性,不加能力)

> 交付对象:实现者(DeepSeek)。**这是最高优先的可用性修复,不是新功能。** 配 ADR-005/006(点头)、v0.11/12(对话)、v0.19(规划)读。
> 背景:真实使用(打 ctfshow i.am.ctfer.com)发现致命问题 —— **对话排了步骤、点开始,一步也没做**。
> 根因:(1) 没配 LLM key 时对话直接拒绝;(2) 就算配了,对话里 AI 只产卡片,建任务/排步骤/起 run 全要操作员去别的面板手点,
> **对话和执行两套割裂、没打通**。结果 agent 的核心价值(说一声就自己去渗、遇险停)根本没兑现。本轮把这条闭环接通。

## 0. 要达到的最终体验(验收即体验)

操作员在对话里打一句"帮我测 https://i.am.ctfer.com" → youkai:
1. 从这句话**起草**一个任务 + 授权范围(scope),用人话摆出来:"我将对 i.am.ctfer.com 开只读扫描,范围就这一个域名,方法只读。确认开工?"
2. 操作员点一次**确认开工**(这一次确认 = 定下授权范围,替代现在那堆手点)。
3. **档 1 只读链立刻自己跑起来**(scan/crawl/probe/fingerprint…),对话里实时播报"正在扫 → 发现 3 个端点 → 在 /api 看到参数反射…"。
4. 跑到**档 2**(要主动探测/写)时**停下**,在对话里弹"我想对 ?id= 做 SQL 存在性探测,批不批?",操作员点头才继续。
5. 发现敏感即停(sensitive_stop),如实报。

**一次范围确认 + 档 2 逐个点头** —— 省心(档 1 全自动)又安全(范围人定、档 2 人批)。不再有"排了步骤却不动"。

## 0.5 不可动摇(继承,一个不松)

- **scope 仍由人确认**:AI 只**起草**任务+scope,第一次开工前操作员**确认一次**范围。AI 不能自己给自己授权打某目标。
- 档 2 仍逐个停人前(ADR-006 的 UI 点头);档 3 不在;candidate≠verified;全过 Guard;prompt 不含目标响应正文。
- "对话直接开工"是把现在"散落在多个面板的手点"合并成"对话里一次确认 + 按需点头",**不是**去掉人的把关。

## 1. 对话能真正执行动作(不只是产卡片)P0 —— 核心

**目标**:对话的 AI 卡片从"给你看、你去别处点"升级成"你在对话里点一下就真的调对应后端端点执行"。

**涉及**:`internal/api/chat.go`、`internal/planner/chat.go`、`web/chat.js`。

**改法**:
- 卡片带**可执行动作**:`scope_draft` → 操作员在对话里点"确认开工" → 前端**直接调** `POST /api/engagements`(建任务+scope)+ `POST .../runs`(起 run),不用去任务台。
- `plan`/下一步卡片 → 点"批准这步" → 直接调对应 approve+execute(档 2)。
- 关键:**执行仍走现有受闸端点**(建任务走 scope 校验、档 2 走 approve+gate),对话只是把"点按钮"搬进聊天流;AI 本身仍不执行(点击是人的动作)。
- 卡片 schema 仍封闭(无改 scope/自 approve/升 verified);点击动作由前端发起、带令牌,是人的点击不是 AI 的调用。

**验收**:对话里点"确认开工"→ 任务建成 + run 起来(不用离开对话);点"批准这步"→ 档 2 执行一次;AI 仍不能自执行;scope 校验/档 2 gate 照常。

## 2. 起 run 后档 1 真的自主跑完 P0 —— 修"一步也没做"

**目标**:确认为什么"开始后不动",保证 run 一起、档 1 链就自主推进到遇档 2/敏感才停。

**要排查并修的断点(实现者逐个验证)**:
- **scope/seed 没接上**:对话建的任务有没有把目标 host 写进 scope + 作为 seed URL?`deriveContext` 要能从 host 资产派生出 base_url,否则引擎 choose 到空、run 立刻 idle=“一步没做”。**修**:对话建任务时把目标 URL 同时写成 scope.include + run 的 seed_urls。
- **引擎 bootstrap**:scope 非空但没有初始资产时,run 要能从 seed URL 先派一个 scan/probe 把面铺开(现在 SeedURLs 有逻辑,确认真的触发)。
- **档 1 全是 needs_approval 的误判**:确认 scan/crawl/probe/fingerprint 这些确实判成档 1、能自治领取执行,而不是被误挡。
- **run 跑完有没有反馈**:run 的每步结果要推给对话/任务台(SSE),让操作员看到"在动",而不是静默。

**验收**:对一个有反射参数的靶场,对话确认开工 → run 自动跑 scan→发现端点→probe→命中→回灌 fact→继续,直到遇档 2(param)停下;全程 ≥3 个档 1 step 真的执行、有 request_id;对话实时显示进度;绝不是"一步没做"。

## 3. LLM key 配置顺畅 + 无 key 退路 P0

**目标**:别再卡在"没配 key 对话就拒绝"。

- **配 key 顺畅**:对话面板在 AI 未配时,不是只甩一句"去设置",而是**当场内嵌一个填 key 的小卡**(provider 预设 + key 框 + 测试连接),填完立刻能用(复用 v0.4/v0.10 的 LLM 配置)。
- **无 key 退路**:没配 key 时,对话输入框旁给一个"用向导直接开工"按钮 → 走 v0.10 向导(填网址→确认→起 run),**档 1 用内置确定性规则自主跑**(不依赖 LLM)。让最低配也能真渗,不是死路。
- 会话密钥缺失导致 key 存不了的问题(日志那条 warning):无会话密钥时引导用 `key_from_env`,或由 start-youkai 自动生成会话密钥(启动器已做,确认生效)。

**验收**:未配 key → 对话里能当场配 key 或一键转向导;配好/走向导后,档 1 自主跑通;内置规则在无 LLM 时能把只读链跑起来。

## 4. 进度与"它在干嘛"看得见 P1

**目标**:任何时候操作员都知道"youkai 现在在做什么、下一步等我什么"。

- 对话/顶栏实时态:`正在扫描(第 N 步)` / `发现 X,正在验证` / `停在档 2:等你批准对 ?id= 的探测` / `完成,去结果看报告`。
- run 的每步经 SSE 推到对话流,成为一条条可读的进度行(不含凭据/正文)。

**验收**:开工后对话里能看到步骤实时滚动;停在档 2 时明确提示等什么;完成时指向报告。

## 落地顺序

1. 模块二(档 1 真自主跑通)+ 模块一(对话能真执行)—— 这两个是"一步也没做"的正解,一起做、先做。
2. 模块三(key 顺畅 + 无 key 退路)—— 保证第一步不卡死。
3. 模块四(进度可见)。

**每步验收锚点**:对话说目标 → 一次确认 → 档 1 自主跑 ≥3 步并实时播报 → 档 2 停下点头 → 继续 → 出报告;
scope 仍人确认、档 2 仍人批、AI 不自执行、candidate≠verified、不含目标正文、过 Guard;无 key 也能走向导+内置规则跑;
`go test ./...` 全绿;门禁仍过。真机靶场(如本地 lab-target)能完整复现这条闭环。

## 一句话

把 youkai 从"你排了步骤它却一动不动"修成"你说一声,它就自己去扫、去探,碰到该你拍板的才停下问你" ——
agent 的意义就在这条闭环上;档 1 自动、档 2 点头、范围你定,一次都没少把关,但也一次都不让你白等。
