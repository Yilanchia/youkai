# DEVPLAN-v0.11:对话式操作 + 委托书自治 + AI 连通状态

> 交付对象:实现者(DeepSeek)。配 ADR-005(本轮决策)、ADR-002(脑)、DEVPLAN-v0.4(LLM 配置)、v0.10(向导)读。
> 目标:做一个**对话式**前端,让操作员用大白话配置与推进渗透;档 2 在一份**人签委托书**范围内自治;
> 并把"AI 通没通/跑到哪"做成一眼可见的状态。不加检测能力,不碰唯一发包通道、档 3 墙、只验不签。

## 0.5 不可动摇(继承 ADR-005,逐条适用)

- 对话里 AI 只有**嘴**:说/建议/起草 scope/起草委托书/排队只读步骤/执行委托书已授权的档 2。它**没有手**去:
  改自己的栅栏(扩 scope、加动作类)、自签委托书、把 candidate 升 verified、碰档 3。这些要操作员签/点。
- **委托书 = high-auth 签名记录**:AI 能起草 JSON,**激活必须操作员用 FAIRY_AUTH_KEY 签**;youkai 只验不签。
- 喂给对话模型的上下文**不含目标响应正文**(攻击者可控 → prompt 注入面),只喂已归一的 fact/trace 摘要。
- 目标请求仍全过 `discipline.Guard`;委托书必须带请求预算 + 时间窗 + 急停,缺则拒绝激活。
- 纯前端 + 薄 API 编排;不动 `discipline`/`gate`/`engine` 安全逻辑。

## 1. AI 连通状态(P0,先做,解决"不知道通没通")

**目标**:随时一眼看到 AI 是"未配 / 已连通 / 配了但连不上"。

- 顶栏常驻状态灯:灰(未配)/ 绿(已连通,显示模型名+延迟)/ 红(配了连不上,显示错误如"401 密钥无效""连接超时")。
- 保存 LLM 配置后**自动调一次** `POST /api/config/llm/test`(已存在,真发 /chat/completions 测 pong),把结果显著显示,不让用户猜。
- 对话框顶部也复用这个灯;未连通时对话输入禁用并提示"先在设置里配好 AI"。

**验收**:配错 key → 红灯 + 真实错误;配对 → 绿灯 + 延迟;未配 → 灰灯且对话禁用并指向设置。

## 2. 对话面板(P0,核心)

**目标**:新增"对话"面板(成为默认首页),操作员打字,AI 回话并**把意图翻译成 youkai 操作的待确认卡片**。

**涉及**:`web/chat.js`(新)、`internal/api/chat.go`(新,薄编排)、复用 `internal/planner`。

**交互模型(关键:AI 产出的是"待确认动作",不是直接执行)**:
- 操作员:"帮我测 example.com 的登录越权"。
- AI 回:一段解释 + 一张或多张**结构化卡片**,卡片类型只有以下几种,每种都带"确认/取消":
  1. `scope_draft`:草拟的 scope(include/方法/建议开的动作类)→ 操作员点确认后进入"待签委托书"。
  2. `mandate_draft`:草拟的委托书(scope + 预授权动作类 + 上限 + 时间窗)→ 操作员**去签**(见模块 3)。
  3. `plan`:接下来要跑的只读/已授权档 2 步骤清单 → 确认后排队给引擎。
  4. `note`:纯解释/答疑(如"api 通没通""现在跑到哪"),无副作用。
- AI **不能**产出"直接改 scope""直接 approve""直接升 verified"的卡片 —— 这些动作在 schema 里不存在。

**后端 `/api/chat`**:接收消息 + 当前 engagement 上下文(已归一 fact/trace 摘要,**不含响应正文**),调 planner 产出**受限 schema** 的卡片 JSON;每次调用落 `planner_calls` 存档(可回放,同 v0.4/v0.7)。解析失败即拒,不执行。

**验收**:自然语言能产出 scope_draft / plan 卡片;卡片未确认不生效;AI 无法产出改 scope/approve/verified 卡片(schema 层拒);对话上下文不含目标正文;每轮落存档。

## 3. 委托书:起草 → 人签 → 激活(P0,栅栏机制)

**目标**:把 ADR-005 的委托书落地成"AI 起草、人签、youkai 验签后生效"的闭环。

**涉及**:`internal/api/mandate.go`、复用 `internal/discipline/highauth.go`(验签)。

**流程**:
- AI 产出 `mandate_draft`(JSON:scope + authorized_tier2_classes[] + max_requests + expires_at + 说明)。
- UI 把它渲染成**人话委托书**:"你将授权 youkai 在 <scope> 上自动执行:SQL 存在性探测、WAF 探测;上限 500 请求;到 <时间> 失效。
  这些动作只判存在、不取数据;期间 AI 不再逐步问你,但你可随时急停。"
- 操作员**签**:给出用 `FAIRY_AUTH_KEY` 生成的签名记录(CLI 生成,或 UI 引导生成命令让其在本机跑;**youkai 不持密钥、不自签**)。
- `/api/mandate/activate` 验签(资产匹配、动作类匹配、未过期)→ 通过则引擎进入"委托书自治"模式。
- **急停** `/api/mandate/stop`:立即撤销委托书,引擎回到档 2 逐步停。

**验收**:draft 未签不生效;签名错误/过期/资产不符被拒;激活后引擎能自动跑已授权动作类的档 2、越界仍停;急停即时生效;全程审计。

## 4. 委托书自治模式接引擎(P0)

**目标**:引擎在"委托书自治"下,把**委托书已授权的档 2 动作类**当作可自治执行(等价于把这些类临时视为"已获授权"),
其余(未授权类、新资产、档 3)仍停。

**涉及**:`internal/engine`(读当前 mandate,扩展 `AutonomousOK` 的判断**仅限 mandate 覆盖的类**)。

**实现要点**:
- 引擎不改 `gate` 的分档;而是在 claim 判定处:`tier==1 || (tier==2 && mandateCovers(capability, target))` 才可自治。
- `mandateCovers` 只认**已验签且未过期**的 mandate;mandate 是数据,**不是 AI 能写的内存标志**(存 PG,激活时写,急停/过期即失效)。
- 预算/时间窗由现有 scope 限额 + mandate 的 max_requests/expires 双重约束,取更严。
- candidate→verified **仍不自动**;每个档 2 执行仍逐请求审计并在对话里播报。

**验收**:激活覆盖 param 的 mandate → 引擎自动跑 param(不再停);未覆盖的 waf 仍停;mandate 过期/急停后 param 立刻回到"停";verified 仍需人确认;审计完整。

## 落地顺序

1. 模块一(AI 连通状态)—— 最小、立刻解决"通没通",先做。
2. 模块二(对话面板 + 受限卡片 schema)。
3. 模块三(委托书起草→人签→验签激活 + 急停)。
4. 模块四(引擎接委托书自治)。
5. 模块五(文档)。

**每步验收锚点**:AI 连通状态一眼可见;对话里 AI 产不出改 scope/approve/verified 卡片;委托书必须人签、youkai 不自签;
引擎自治只覆盖已验签 mandate 的动作类、越界即停、急停即时;对话上下文不含目标正文;档 3 不可达;`go test ./...` 全绿。

## 一句话

让 youkai 能聊天、能在你签的委托书里自己干活 —— 但那扇"AI 自己动手改规则"的门焊死:
它能起草一切,激活要你签;它够得到圈里的每一步,够不到圈本身。
