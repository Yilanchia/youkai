# youkai 暂停说明(2026-11-16)

> 这不是烂尾,是**止损 + 选对战场**。记录它到了哪、为什么暂停、以后想捡起来从哪接。

## 为什么暂停

维护者用 DSH + Verdex/Fairy 插件实测:对于"快速打靶场、出 flag"这类场景,DSH 直接驱动强模型**更快更省心**。
youkai 想在这件事上赢 DSH,先天不占优——它的价值从来不是"更快打穿",而是"授权范围内只读取证、每一发可辩护、该停就停"。
同时维护者有一个方向更稳、已上线真机的防御 agent(Nightwatch,`D:\nightwatch`),决定把精力与预算收回到那边。

这个判断是对的:**选对战场,而不是硬追一个本该用 DSH 的场景。**

## youkai 到了哪(暂停时的真实状态)

- 单体 Go 平台,已公开发布(github.com/Yilanchia/youkai),~28k 行实现 + ~11k 行测试,66 个受闸能力。
- 架构完整:纪律脊柱(唯一发包通道)、档位墙(档3编译期隔离)、PG 账本、白盒源码分析、
  8 类 sink 存在性探针、反 AI-逆向致盲、多链型规划、证据先行报告、CI + 5 个安全门禁。
- v0.24 已落地:**模型当大脑、平台当闸**(ADR-007)——模型主导规划,每个动作执行前仍由 gate 重新分档,
  模型不能自升档位/自放行,档2停人前,档3碰不到。
- DSH 式对话界面已重做(v0.25 ui)。
- 本地有 7 个提交未推送到 GitHub(`git push` 即可同步)。

**它是一个能跑、测试全绿、架构自洽、已发布的东西。暂停时它是资产,不是债务。**

## 核心资产不会浪费(和 Nightwatch 同源)

youkai 和 Nightwatch 是一体两面:一个盯目标(攻击面取证),一个盯机器(防御取证),**共享同一个内核**——
纪律、证据、只读默认、留痕、该停就停。youkai 上打磨出来的这些,哪天 Nightwatch 需要"攻击面视角"或"证据闭环"时,
可以直接搬:`internal/discipline`(scope/guard/审计)、`internal/ledger`(append-only + 触发器)、
证据四要素、档位放行模型、DSH 式对话壳。**学到的东西一样不丢。**

## 以后想捡起来,从哪接

- 读 `docs/WHERE-WE-STAND.md`(定位)+ `docs/ADR-007`(最新大脑模型)。
- 决策链:ADR-001→007,冲突以新为准。
- 最该先做的不是加能力,是:找一个**真实授权、且适合"取证而非打穿"的场景**(比如给甲方出一份可复核的授权渗透报告),
  在那个场景里 youkai 才显出它比 DSH 强的地方——可辩护、留证据、不越界。CTF 不是它的主场。

## 一句话

youkai 没失败,它只是挑了最难证明自己的那个场景(打靶场出 flag)去跟 DSH 比。
它真正的主场——可辩护的授权取证——还没好好打过。暂停,是为了不在错的战场上继续耗;它随时能从这里接着走。
