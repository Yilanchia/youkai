## 四、v0.11:对话 + 委托书(今天最大的一步)

### AI 状态灯
顶栏常驻,点一下跑真探针。实测本机 DeepSeek:`● deepseek-flash · 2218 ms`。

### 对话面板(默认首页)
你说人话,它回 **words + 卡片**。卡片只有四种:`scope_draft` / `plan` / `mandate_draft` / `note`。

**schema 就是墙**:`approve`、`verify`、`set_scope` 这三种卡片在解析器里**不存在**,模型硬写会被丢掉并提示"丢弃了 N 条"。`plan` 只接受只读能力白名单。喂给模型的上下文**不含响应正文**(页面内容可能是攻击者写的)。

### 委托书:AI 起草,人签,youkai 只验不签
- 签名器是**独立二进制** `youkai-sign`:`youkaid` 里没有签名代码链接进去,所以"youkai 批准了自己"不可表示。
- 签名覆盖规范化后的完整 payload,改一个字段就失效。
- 激活要过十道检查:签名、schema、依据、批准人、资产、到期、动作类、预算、目标在范围、**护照开关已开**。

真机实测(本机靶场):

```
激活            → classes=[param]  remaining=50
param 跑完       → status=done  approved=False  under=mandate  remaining=44
急停            → active=false
再发一个 param   → status=needs_approval(回到逐步审批)
```

`approved=False` 是关键:它没走过批准表。

### 引擎怎么放行
```
tier 1                          → 自己跑(不变)
tier 2 + 委托书覆盖该类+该目标   → 自己跑,标 under=mandate
tier 2 其它                     → 停在待办审批(不变)
tier 3                          → 门禁直接拒,委托书也够不到
```
委托书读失败 = **当作没有委托书**(fail closed);执行前再读一次,所以跑到一半摁急停会在下一个请求前拦住。

### 和 ADR-005 的一处偏差(故意的)
ADR 说"委托书把动作类视作已获授权"。我按**更严**的一侧做:委托书还必须要求护照里对应开关已打开。
理由:签名只该决定"要不要每步问你",不该解锁"这单里禁止的事";失败点在激活时,不在跑到一半。

- `audit_log.request_id` 全局唯一:测试夹具的 id 必须带随机后缀。
