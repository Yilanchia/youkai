# ADR-006:自主只读 + 风险处停下点头(拆掉签名仪式,校正 ADR-005)

> 状态:已决定(2026)。**推翻 ADR-005 的"签名委托书作为档 2 默认门槛"**,也**收回 ADR-005 的"整站预授权动作类"**。
> 回到最朴素正确的模型:**AI 自主跑只读,碰到风险动作或敏感发现就停下,人在 UI 里点一下批准才继续。**
> 读者:维护者 + 实现者(DeepSeek)。自包含。

## 背景(真实使用反馈)

操作员实测反馈:签名(`youkai-sign` + `FAIRY_AUTH_KEY`)非常难弄、对话历史不显示、agent 不能自主把探测跑完。
并澄清了真实诉求:**不是要 AI 自己渗透到底,而是要 AI 在渗透过程中"发现不对就及时止损、交人审批、批了再继续"。**

诊断:ADR-005 的签名委托书是过度设计。病根是 `executeIntent` 对网络目标档 2 硬性要求 HMAC high-auth 记录(428 墙),
它既难用,又把 agent 的探测卡死在墙后(`allow_active_probes` 要签名才放行)。三个症状同一病根。

## 决策

1. **默认门槛 = UI 点头,不是签名。** 档 2 动作与敏感发现触发"停下 + 一张待批卡";操作员在本机 UI 读清楚后点"批准",
   才执行这**一个**动作。移除 high-auth 签名作为档 2 执行的**必需**前置。
2. **high-auth 降级为可选高级项。** 谁需要加密级把关(远程目标、更严部署)可在设置里开启"要求 high-auth";默认关。
3. **自主只读不变、止损点不变**:tier-1 自治照跑;tier-2 + 敏感命中(sensitive_stop)停下等点头。
4. **回收 ADR-005 的委托书/整站预授权**:不再有"签一份委托书、整站预授权动作类"。改回**逐个风险动作点头**(更符合"发现不对就停")。

## 为什么"UI 点头"在本场景足够安全(不是放松)

- youkai v1 是**本机、单操作员、仅 127.0.0.1、令牌鉴权**的控制台(ADR-003)。能点到"批准"的,只有此刻坐在这台机器、
  持有令牌的人 —— 那就是人类把关本身。
- 真正的安全属性 **"档 2 执行必须有一次独立的人类动作"没有丢**:批准行 + 一次性消费 + candidate≠verified 的数据库触发器全部保留。
  改的只是那次人类动作的**形式**:从"去 PowerShell 跑签名工具"变成"在 UI 点一下"。
- HMAC 签名源自 Fairy 的"授权人≠执行者"多方场景;在单人本机场景它是无收益的仪式,还逼人放弃或设弱 key 绕过 —— 拆掉更安全。
- youkai 档 2 构造上无害(只判存在/单次/不取数据);真有破坏力的档 3 编译期墙外。这个门槛用"看清+点头"足够。

## 挪不动的线(任何整改不得破)

1. **AI 不能自己点批准。** 批准是操作员在 UI 的点击(令牌鉴权的人类动作);对话里的 AI/planner 代码路径**永不**调用 approve/execute。
2. **批准仍一次性、绑定这一个动作**:批准行 + `ConsumeApproval` 不变;执行一次即消费,下一步要新批准。
3. **candidate→verified 仍须操作员确认**;**档 3 仍编译期墙外**;**目标请求仍全过 discipline.Guard + 逐请求审计 + 数据最小化**。
4. 敏感发现(私钥/凭据等)仍触发 sensitive_stop,停下交人。

## 与既有决策的关系

- ADR-002 的脑四角色、唯一发包通道、LLM 只提议、档 3 墙:**有效**。
- ADR-003 单操作员本机形态:**有效**,本 ADR 正是基于它才敢用 UI 点头替代签名。
- ADR-005:**本 ADR 取代其"签名委托书 + 整站预授权"**。对话式界面本身保留(ADR-005 模块 1、DEVPLAN-v0.11 的对话面板继续做),
  但对话里 AI 仍只有嘴;放行从"签委托书"改为"逐步 UI 点头"。
- 冲突处以本 ADR 为准。

## 一句话

把门从"要你去签一张密码学委托书"改成"要你看一眼、点个头"。AI 在只读里自己跑、碰到有风险就停下问你 ——
人类把关一分没少,只是不再逼你做仪式。
