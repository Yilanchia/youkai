# IMPL-STATUS v0.20 — 打通"说一声就真渗"的闭环

> 日期:2026-11-15 · 承接 DEVPLAN-v0.20 · `go test ./...` 全绿 · 真机靶场跑通
> **这轮没加任何能力**:它修的是"排了步骤、点开始,一步也没做"。

## 真因(三个,都定位到代码)

用户报告的是"对话排了步骤、点开始,一步也没做"。复现后找到三个独立断点:

### 1. 跑到了上一个作业(最致命)

向导建完任务后**没有把当前作业切过去**。于是点"开始扫描"时,run 发给了**上一个** engagement ——
新任务里 0 资产 0 步骤,看着就是"它一动不动"。

**复现证据**:新建作业 12,点开始 → run #22 落在作业 **11** 上,作业 12 一条 run 都没有。

修:`web/wizard.js` 建完立刻 `selectEngagement(created.id)`;对话里"确认开工"同样处理。

### 2. 依赖停在未批准的档 2 步骤时,run 报"idle"

对话的 plan 常把 tier-2(登录)放第一步,后面的只读步骤 `deps` 指向它。于是:

- 登录 park → 只读步骤**永远不可领取** → run `steps: 0`、`idle`;
- 操作员看到的是"一步也没做",而不是"在等你批第 1 步"。

修:`internal/engine` 新增 `waitingOnApproval`,把原因说成人话:

```
还在等一个批准:#126 param(批准后 #127 headers 会自动接着跑)
```

### 3. 存着的模型 key 解不开 → 规划器被静默关闭

日志里只有一行 `WARNING: LLM configuration ignored: ... 解密 llm 失败`,界面照旧显示"AI 未配置"。
根因是会话密钥换过,`resolveLLMKey` 解不开旧密文 —— 用户配过 key,却永远用不上。

修:服务端记住这个原因(`LLMProblem`),`/api/config` 与 `/api/config/llm` 都带 `problem` 字段;
对话面板顶部红条直说"已保存的模型 key 解不开(会话密钥换过?),请重新填一次"。

## 改动清单

- `web/wizard.js`:建完任务**切换到它**(修 bug 1)。
- `web/chat.js`:`scope_draft` 卡片一键「确认开工」= 建任务 + 起 run;批准档 2 后**自动续跑**;
  输入框旁加「用向导直接开工」;顶部显示配置问题红条。
- `internal/engine`:run 停下的原因说清"在等哪个批准、批准后谁接着跑"(修 bug 2)。
- `internal/api`:run 无 seed 时从护照的 include 派生(裸主机补 scheme);对话在无模型时**不再报错**,
  而是指路;`/api/config` 与 `/api/config/llm` 带 `problem`(修 bug 3)。
- `internal/api/llm.go`:`LLMProblem` 记录"存着但装不上"的原因。

## 没做的(如实)

- **SSE 逐步滚进对话流**没做:进度现在体现在"开始"面板的运行记录、对话状态行的复盘、以及 run 的 stop_reason;
  真正的"每一行步骤推进对话"还差一层。
- **对话不经过模型也能生成 plan 卡片**没做:无模型时只给指路,不给结构化 plan(内置规则会在 run 里自己排)。
- **`accounts_provision` 依赖账号清单**:没有 manifest 时它会失败(实测 502),这条链在这种环境下
  只能靠别的档 2 步骤演示 —— 环境限制,不是链路问题。

## 一句话

"说一声就真渗"这条链现在是通的:**一次确认开工 → 只读自己跑 → 遇险停下说清在等谁 → 点头后接着跑**。
修的是断点,不是纪律:scope 仍人确认、档 2 仍人批、AI 仍只提议。
## 评审回灌(Claude 的 v0.20 复审)

复审补了一个我漏掉的死路:**第一次用、一个作业都没有时,连话都说不了**(对话绑定 engagement)。
做法是首条消息自动建一个**只有名字、护照为空**的草稿作业来承载对话。

我复核后的结论与一处修正:

- **安全性成立**:空护照的作业 `startRun` 直接 400(实测:「这个作业还没有护照(include 为空)」),
  这条路径不授予任何目标权限;scope 仍要操作员点 `scope_draft` 的「确认开工」。
- **修正**:草稿作业存在时,「确认开工」现在**给这个草稿补 scope**,而不是再建一个作业。
  否则 run 与报告会落在另一个 engagement 上,而对话历史还挂在旧的那个 —— 操作员等于在看另一个任务。
  实测:同一作业 15 上补 scope + 起 run,作业总数不变(14),3 个档 1 步骤执行、11 次请求、7 条发现。
