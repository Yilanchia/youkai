# ADR-007:模型当大脑,平台当闸 —— youkai 存在的意义所在

> 状态:已决定(2026-11-16)。这是 youkai 自立项以来**最根本的一次方向校正**。
> 起因:真实使用后维护者的判断 —— "现在这样还不如直接用 DSH + Verdex + Fairy 两个插件,DSH 驱动强模型自主编排、
> 自己把 flag 拿下、很省心;youkai 把大脑做成了确定性规则 + 只会产卡片的对话壳,真正的智能没接进来,
> 沦为按规则挨个跑、每步等人点的死机器,那它就没有存在意义。" 这个判断是对的,本 ADR 据此转向。

## 问题的根(诚实复盘)

前面 v0.1→v0.23 一路在加检测能力、守红线、修体验,但**一直回避了核心**:让模型真正当这个平台的大脑。
现状是:引擎靠**确定性规则**派单(deriveContext + 规则表),LLM 只在规则没覆盖时"补位提议",对话里 AI 只产**待确认卡片**。
结果——模型几乎不参与真正的决策,平台空心,智能上不如 DSH 直接驱动一个强模型。花钱充的 API,没用在刀刃上。

## 决策:大脑交给模型,安全焊在平台

1. **模型当大脑(要的就是 DSH 式智能)**:模型自主规划、自主串链、自主推进 —— 看到已归一的证据,自己决定
   下一步测哪、怎么分析、怎么把线索串成攻击链,一路推到目标(含把 flag 的路走通)。不再是"规则派单、模型补位",
   而是"模型主导、规则兜底"。
2. **安全焊在平台(youkai 比 DSH 多出来的意义)**:模型再聪明、再被诱导/破甲/注入,**越不过平台的闸**——
   - 任何碰目标的动作,必须过 `discipline.Guard`(scope + 逐请求审计),越界阻断。
   - 档 1 只读:模型可自主执行。
   - 档 2 利用/写:模型可**自主规划和推进到这一步**,但执行前仍停人前点头(ADR-006),或在人签的范围内放行。
   - 档 3 自动打穿:编译期墙外,模型碰不到。
   - 放行权在**闸门代码**,不在模型。模型决定"想做什么",闸门决定"能不能做"。

## 为什么这样既智能又安全(命脉)

**DSH 的安全 = 模型自觉(破甲即失效)。youkai 的安全 = 平台闸门(破甲也越不过)。**

- "自主"和"受闸"不矛盾,是**分层**的:
  - **第一层(选路/分析/串链)完全交给模型** —— 这是智能,放开。
  - **第二层(能不能真发包、真执行利用)完全焊在平台** —— 这是安全,写死。
- DSH 把两层都交给模型自觉;youkai 把第一层给模型、第二层焊在平台。
- 结论:**同样的 DSH 式智能,但模型失守时平台不失守。** 这是 youkai 不可替代的意义 —— 你敢把它接到一个会被
  prompt 注入、会被破甲的模型上,因为就算模型被策反,它也只能"想",发不出越界的包、执行不了没批准的利用。

## 对既有决策的影响

- ADR-002(脑四角色、唯一发包通道、LLM 只提议不放行、档 3 墙):**全部有效**。本 ADR 把"LLM 只提议"的
  **提议范围大幅放开**(从"规则没覆盖才补位"变成"模型主导整个规划"),但"不放行"这条**一字不改** —— 放行永远是闸门/人。
- ADR-006(档 2 UI 点头、真/假停止点):有效。模型自主推进到档 2 仍停人前。
- ADR-003/004/005:形态与单体化不变。
- 冲突处:本 ADR 定义"模型主导规划"的大方向;具体档位放行规则以 ADR-006 为准。

## 落地方向(细节见配套 DEVPLAN)

- 对话/引擎改成**模型主导的 agent 循环**:模型看图(脱敏证据)→ 自主决定下一批动作 → 平台按档位放行(档1直接跑、
  档2停人前)→ 结果回灌 → 模型再决策,直到目标达成或遇真停止点。像 DSH 那样连续推进,但每个碰目标动作都过闸。
- 模型的决策、推理、每步都落账可回放(延续可复现纪律)。
- prompt 仍只喂归一证据,不喂目标响应正文(防注入是纵深防御的一层,但**主防线是闸门**,不是 prompt 干净)。

## 一句话

把大脑还给模型,让 youkai 像 DSH 一样智能省心;把闸门焊在平台,让它比 DSH 多一条"模型失守也不出事"的命 ——
模型负责有多聪明,平台负责绝不出格。这才是一个既能打、又让人敢托付的平台,也才是 youkai 存在的理由。
