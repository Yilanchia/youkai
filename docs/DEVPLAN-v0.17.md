# DEVPLAN-v0.17:agent 规划智能 — 会从白盒+黑盒证据推下一步、会组链,而不是堆检测项

> 交付对象:实现者(DeepSeek)。配 ADR-002(planner 只提议)、ADR-005/006、v0.7(trace)、v0.13(假设)、v0.14/15(探针)读。
> 目标:让 planner/对话从"按规则派检测"升级成"从已有证据推断最该走的下一步、会把多步串成链"——更像脑,而不是更长的检测清单。
> 不新增检测能力;只改"怎么决定下一步"。安全边界全不变:LLM 只提议,放行归闸门,风险停人前。

## 0. 现状与目标

现在引擎派生基本是"见到 X 资产 → 派 Y 检测"的规则映射(deriveContext + 规则表 + 白盒假设映射)。够用但不"聪明":
- 不会综合多条 fact 判断"这条链更值得走";
- 不会把"白盒假设 + 账号归属 + 已有 trace"拼成一条有依赖的多步链;
- 对话里 AI 建议偏单点,不成体系。

v0.17 让规划从证据里推理,但**不给它任何新动作**——它能提议的仍是 v0.1~v0.16 那些受闸能力,只是更会选、更会排序、更会组链。

## 0.5 不可动摇(继承)

- LLM 只提议类型化 intent;放行/批准/升 verified 归闸门与人(ADR-006);prompt 不含目标响应正文(只喂归一 fact/trace/假设摘要,防注入)。
- 规划的任何档 2 步骤仍停人前;组出的链不等于自动执行链——每个档 2 节点都是一次独立点头。
- planner 调用全落 `planner_calls` 可回放;新增的"推理"也要可回放(存它看到的证据 + 产出的链)。
- 确定性兜底不删:LLM 不可用时,规则规划照跑。

## 1. 证据加权的下一步选择 `internal/engine`（P1)

**目标**:planner tick 时,不只"有 ready 就派",而是对候选下一步**排序**:哪条链前置证据最全、价值最高、成本最低、没被 trace 覆盖过。

**要点**:
- 给候选 intent 算一个**可解释的优先分**(证据完整度 + 漏洞类价值 + 预算成本 + 是否已被 trace 覆盖),分数和理由都记进图(可审计,不是黑箱)。
- 高分先派;同分按确定性顺序(可复现)。
- 这是**排序**,不改放行规则:档 2 仍停人前,只是"先停在更值得的那一步"。

**验收**:两条 ready 链,证据更全的先被派;排序理由可查;档 2 仍停;同输入可复现。

## 2. 多步链组装(assumption-aware chaining)P1

**目标**:把"白盒假设 + 账号归属 + 已确认 fact"拼成一条**有依赖的多步链**,而不是孤立单点。

**要点**:
- 例:白盒假设"/orders 可能 IDOR" + 账号层有两身份 + 已知归属 → 组一条链:登录两身份(档2,点头)→ compare(档1)→ 命中则升 candidate。每步依赖上一步产物。
- 链以**依赖图**表示;任一步是档 2 就在那停人前;人批后继续下一步(ADR-006 的"自主只读+遇险点头"在链上同样成立)。
- 链的每一步都标"为什么走这步"(从哪条证据推来),写进探索图血缘。

**验收**:给"白盒假设+双身份"→ 组出 IDOR 验证链;链含档 2 步时停人前;每步血缘可查;点头后推进。

## 3. 对话里的推理呈现 `web/chat.js` + `internal/planner`（P2)

**目标**:对话里 AI 不只给单条建议,而是给"我从这些证据看,建议这条链,理由是…"的**成体系提案**(仍是待确认卡片)。

**要点**:
- AI 产出 `plan` 卡片可以是**一条链**(多步 + 依赖 + 每步理由),操作员整体看、逐步批(档 2 步逐个点头)。
- 卡片仍是受限 schema:不能出 approve/改 scope/升 verified(v0.11/12 红线)。
- 推理依据只引用归一证据,不塞目标正文。

**验收**:对话能给出带理由的多步链提案;档 2 步逐个点头;schema 不含越权卡片;prompt 无目标正文。

## 4. 规划质量 bench P2

- bench 增"规划质量"维度:同靶场下,衡量到达一条 verified 发现用了几步/几次请求/几次人工点头(越少越好,但不以牺牲纪律换)。
- 只对本机靶场,不外推。

**验收**:bench 输出规划效率指标;越界=0;不因追求"少步数"而跳过档 2 点头。

## 落地顺序:1 证据加权选择 → 2 多步链组装 → 3 对话推理呈现 → 4 规划 bench。

**验收锚点**:LLM 只提议、放行归人;组链不等于自动执行、档 2 逐个点头;排序/链血缘可解释可复现;planner 调用可回放;
确定性兜底在;prompt 无目标正文;`go test ./...` 全绿。

## 一句话

让 youkai 从"按清单挨个测"变成"看着证据想:下一步最该挖哪、怎么把线索串成链" —— 更会规划,
但每一步该停的地方照样停:聪明用在选路上,不用在越过闸门上。
