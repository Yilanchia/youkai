# DEVPLAN-v0.24:模型主导的 agent 循环 —— 让 youkai 像 DSH 一样自己推,闸门焊在平台

> 交付对象:实现者(DeepSeek)。配 ADR-007(本轮决策,必读)、ADR-006(档位放行)、v0.22(托管循环)读。
> 目标:把引擎从"规则派单、LLM 补位"翻成"**模型主导规划、规则兜底**"——模型看证据自主决定下一批动作、连续推进到目标,
> 每个碰目标动作仍过平台闸(档1放行、档2停人前、档3墙外)。这是让 youkai 不再是"死机器"、而有存在意义的那一刀。

## 0. 现状:模型被架空了(已核实)

- `derive` 里一串确定性 `rule` 先跑;`Proposer`(LLM)只在规则派不出东西、且 `llmRounds < defaultMaxLLMRound(=2)` 时补位。
- 结果:**模型几乎不参与决策**,平台靠硬编规则挨个派已知检查。智能上不如 DSH 直接驱动强模型。
- ADR-007 的转向:模型主导整个规划,规则退到兜底。

## 0.5 不可动摇(ADR-007 的命脉:自主≠放行)

- **模型自主的是"选路/分析/串链"(第一层),平台焊死的是"能不能真执行"(第二层)。** 两层分开:
  - 模型可以**决定**想做任何动作;**能不能做**由 `gate` + `discipline.Guard` + ADR-006 决定,与模型无关。
  - 档 1 只读 → 模型可自主连续执行。档 2 → 模型可自主推进到此并提议,**执行仍停人前点头**。档 3 → 墙外,模型碰不到。
- **放行权永远在闸门/人,不在模型。** 模型被破甲/注入/策反,最多让它"想做坏事",但发不出越界包、执行不了没批准的利用——这是 youkai 对 DSH 的核心优势,**一字不动**。
- prompt 只喂归一证据(fact/trace/假设摘要),**不喂目标响应正文**;这是纵深防御一层,但主防线是闸门不是 prompt。
- 模型每步决策 + 推理落 `planner_calls` 可回放;无模型时规则兜底,平台不瘫。

## 1. 翻转主循环:模型主导 `internal/engine`(P0,核心)

**目标**:每轮 derive 优先问模型"看这些证据,下一批该做什么",规则退为兜底。

**改法**:
- `derive` 的顺序改为:**① 先让 Proposer(模型)基于当前图(脱敏证据 + 已做 trace + 白盒假设 + 账号/归属)产出下一批 typed intents;② 规则只在模型不可用、或模型这轮没产出可执行动作时兜底。**
- 去掉 `llmRounds < 2` 的硬上限,改为**连续推进**:模型主导的循环可以一轮轮跑下去(像 DSH),直到:遇真停止点(档2需批/敏感/idle)、或触及**总预算**(步数/请求/时间,复用 v0.22 的 SuperviseBudget + scope.max_requests)。
- 模型产出的每个 intent **仍走 gate 分档 + EnsureIntent**:档1进自治队列(模型可连续跑),档2落 needs_approval(停人前)。模型不能给自己的 intent 标低档——tier 由 `gate.Classify` 定,和 v0.18/19 一致。

**验收**:给一个有多类线索的靶场,模型主导下**连续自主**派 probe→发现→顺着发现自己决定下一步(不靠硬编规则列表),一路推进;遇档2停人前;无模型时规则兜底仍能跑;模型想把档2标档1无效(gate 覆盖)。

## 2. 模型看得更全、决策更强 `internal/planner` + `ProposeRequest`(P0)

**目标**:给模型足够的上下文做真正的规划(像 DSH 那样),但全脱敏。

**改法**:
- `ProposeRequest` 扩充(仍全脱敏):当前所有 fact/finding 摘要、白盒假设、账号归属、已做 trace、每条发现的 kind/where/证据流水号、可用能力白名单 + 各能力的档位。
- prompt 明确模型的角色:"你是这个授权渗透任务的规划大脑。基于下面的证据,决定接下来最该做的动作(从白名单里选),可以是多步。档2动作会停下等人批——你照常提,系统会停。目标是把授权范围内能证实的影响证到。不要编造没有证据支持的东西。"
- 输出 schema:一批 `{capability, args, rationale, expected}`,capability 必须在白名单内;越界/未知一律被 gate 挡。
- **不含目标正文**,证据只到归一 fact + 流水号。

**验收**:模型能基于"git 泄露 fact + 反射参数 fact + 两身份"自主规划出合理的下一批(如:对反射参数提议 param 档2、对两身份提议 compare 档1),rationale 说得清;schema 外的产出被丢;prompt 无目标正文。

## 3. 对话 = 自主 agent 的指挥窗 `web/chat.js` + `internal/api/chat.go`(P0,体验)

**目标**:对话里说"打这个站",模型就当大脑自己推进,全程时间线实时滚(v0.21/22 已有),你只在档2拍板。像 DSH 聊天窗那样省心。

**改法**:
- 对话确认开工后,引擎进入**模型主导的托管循环**:模型连续规划+推进(档1自动、档2停人前),步骤实时流进时间线。
- 对话里模型的"推理"(为什么走下一步)作为 reflect/plan 事件显示(v0.19/21 已有管道)。
- flag 这类:模型会自主把只读侦察→发现→"怎么打"的路推到底并讲清(v0.23 的利用方案),**真正扣扳机的档2/利用动作停人前**——它把 flag 的路给你铺到门口,门由你推开(符合 ADR-006/007)。

**验收**:对话说目标→模型自主连续推进→时间线实时滚+带推理→有发现时给"怎么打怎么修"→档2处停人前点头→继续。全程不用手点"开始/下一步",像 DSH 一样省心;但档2一步都没自动越过。

## 4. 可回放与兜底 P1

- 模型每轮决策(prompt/model/raw/parsed/选了什么)落 `planner_calls`,时间线可回看"它当时为什么这么想"。
- 无 LLM key / 模型挂:自动退回确定性规则主导(现在的行为),平台不瘫,只是不那么聪明。

**验收**:模型决策全程可回放;拔掉 key 后规则兜底跑通。

## 落地顺序

1. 模块二(给模型全脱敏上下文 + 规划角色)——先让模型看得全、会规划。
2. 模块一(翻转主循环:模型主导、规则兜底、连续推进、仍过闸)——核心。
3. 模块三(对话指挥窗:自主推进 + 档2停人前)。
4. 模块四(可回放 + 兜底)。

**每步验收锚点**:模型主导连续自主推进(不靠硬编规则列表);每个碰目标动作过 Guard、档1自动/档2停人前/档3墙外;
模型不能自升档位、不能自放行、不能自升 verified;prompt 无目标正文;决策可回放;无模型时规则兜底;
不hack-back、不自动打穿;`go test ./...` 全绿;5 个安全门禁仍过。

## 一句话

把大脑真正交给模型,让 youkai 像 DSH 那样自己想、自己推、省心;但每一个碰目标的动作都撞在平台焊死的闸上 ——
模型有多聪明就使多聪明,平台该拦的一步都不松。智能是模型给的,敢托付是平台给的,缺一个 youkai 就没意义。
