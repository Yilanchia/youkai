# DEVPLAN-v0.22:harness 托管体验 —— 一个窗口、自己跑到真停止点、该你拍板才停

> 交付对象:实现者(DeepSeek)。配 v0.20(对话开工)、v0.21(步骤流)、ADR-006(点头)读。**纯体验/托管,不加能力、不碰红线。**
> 目标:把 youkai 的对话做成 DSH / Claude 聊天窗那种 harness —— 一个窗口里:你说话、AI 回话、工具调用+结果实时滚;
> agent **自己托管着往下跑到真正的停止点**,不用你每 10 步手动续;只在该你拍板处(档 2 / 敏感 / 需决策)停下问你。

## 0. 现状三个断点(已核实)

1. **假停止点当真停**:run 跑到 `max_steps=10` 就 `FinishRun` 结束,明明档 1 还有得跑,却要人再点一次 run。托管感断在这。
2. **对话和步骤流两块面板**:DSH/Claude 是**一条时间线**(你说的话、AI 的话、工具调用、结果混排);youkai 现在对话一块、步骤流一块,割裂,不像"跟一个 agent 对话"。
3. **托管不够顺**:说一句 → 点"确认开工" → 盯着 → 10 步后还要续。应该是"确认一次 → 它自己跑完整条只读链 → 只在该你拍板处停"。

## 0.5 不可动摇(继承,这是托管的边界)

- **区分真/假停止点**(本版核心纪律):
  - **真停止点(必须停,交还人/结束)**:`needs_approval`(档 2)、`sensitive_stop`(敏感数据)、`idle`(没得跑了)。这些**绝不自动跨越**。
  - **假停止点(可自动续)**:`max_steps`(只是防单次跑太久)。托管层自动开下一轮,直到撞上真停止点。
- 托管 = 自动跨越假停止点,**从不**自动跨越真停止点。档 2 仍每个单独点头、敏感仍停、scope 仍人定、AI 不自执行、candidate≠verified —— 全不动。
- 自动续有**总预算上限 + 可随时停**:不是无限跑;给一个整体步数/时间/请求上限(复用 scope 的 max_requests),到顶就停并说明。操作员有"停下"按钮随时中止。
- 事件仍脱敏(v0.21 纪律):播报不含正文/凭据。

## 1. 托管自动续跑 `internal/api/server.go` + `internal/engine`(P0,托管核心)

**目标**:run 停在 `max_steps` 时,只要还有可领的档 1 工作,**自动开下一轮**,直到撞上真停止点(needs_approval/sensitive/idle)或触及总预算。

**改法**:
- `startRun` 的后台 goroutine 改成循环:`Run` 一轮 → 看 `rep.Stop`:
  - `max_steps` 且未触总预算 → 记一条"继续"事件,立刻再 `Run` 一轮(同 run_id 累加,或新一轮挂同一 run)。
  - `needs_approval` / `sensitive` / `idle` → **停,FinishRun**,播报真停止原因。
- 总预算:引入 `run.budget`(总步数上限,比如 50;或直接用 scope.max_requests 作硬顶)。到顶停、说明"已达本次托管预算,点继续可再托管一程"。
- 自动续的每一轮之间发一个 `phase:"derive"` 事件("继续:还有 N 个只读步骤"),让流看起来是连贯托管,不是断续。

**验收**:一个档 1 链需要 >10 步的靶场,确认开工后**自动跑完整条**(不用手点续),中途步骤连续滚;遇档 2 真停;到总预算停并提示;"停下"按钮能即时中止。单测:mock 一个 15 步只读链,托管循环自动跑到 idle、期间档 2 仍 park。

## 2. 一条时间线:对话 + 步骤流合并 `web/chat.js` + `web/stream.js`(P0,体验核心)

**目标**:把对话气泡和步骤流**混排进同一条滚动时间线**,像终端 agent / Claude 窗口:

```
你:帮我测 https://xxx.challenge.ctf.show
youkai:我要对 xxx.challenge.ctf.show 开只读扫描,范围就这一个域名。确认开工? [确认][改范围]
  ▸ 扫描 xxx.challenge.ctf.show       tier1  ✓ 5 个端点
  ▸ 探测 /search?q=…                  tier1  ✓ 参数反射 (R0007)
  ↳ 命中确认"反射"假设,接下来看 DOM 上下文
  ▸ 读 /.git/config                   tier1  ✓ 200 git 配置可读 (R0009)
  ⏸ 想对 ?id=… 做 SQL 存在性探测        tier2  等你拍板 [批准][拒绝]
youkai:只读这程跑完了,发现 2 条候选、1 处要你决定。要我继续吗?
```

**改法**:
- 一个滚动容器,按时间顺序混排:user 气泡、assistant 气泡、step 行(derive/exec/reflect/stop)、档 2 停人前行(内联按钮)。
- step 行样式延续 v0.21(图标+能力名+目标+档位+摘要+request_id),但**嵌进对话流**,不再是独立面板。
- 顶部活动条:`托管中(第 N 步)… / 停在档 2 等你 / 已达预算 / 完成`,带"停下"按钮。
- 刷新后整条时间线可从库重放(chat 历史 + run-steps 按时间 merge)。

**验收**:一个窗口里能看到"你说→AI 应→步骤滚→停人前→AI 小结"连贯一条线;刷新不丢;档 2 行就地点头;看起来就是在跟一个 agent 对话。

## 3. 托管的"小结 + 下一步"回合 `internal/api/chat.go` 或前端(P1)

**目标**:托管跑到真停止点时,AI 用一句话**小结并给选择**,像 harness 一轮结束那样,而不是干停。

**改法**:
- 停在 idle/预算:AI 小结"这程只读跑完,发现 X 候选 Y 处待定,要继续深挖/出报告/换目标吗?"(纯播报,不自动做)。
- 停在 needs_approval:"有 N 个要你拍板的动作(见上),批了我接着跑。"
- 这些小结可以是确定性模板(不依赖 LLM 也有),有 LLM 时更自然。

**验收**:每次托管停下都有一句人话小结 + 明确选项;无 LLM 时用模板;不自动执行任何后续。

## 4. 收尾

- README「对话式用法」更新成"一条时间线 + 托管"的说明与示意。
- `start-youkai` 提示操作员:确认开工后它会自己跑,遇险会停下问。

## 落地顺序

1. 模块一(托管自动续到真停止点)—— 托管核心,先做;真/假停止点区分是纪律重点。
2. 模块二(对话+步骤流合并成一条时间线)—— 体验核心。
3. 模块三(停下时的小结回合)、模块四(文档)。

**每步验收锚点**:自动跨越 max_steps、绝不自动跨越 needs_approval/sensitive;总预算+停下按钮有效;
一条时间线连贯、刷新不丢、档 2 就地点头;事件脱敏;档 2 仍单独点头、candidate≠verified、AI 不自执行;
`go test ./...` 全绿;门禁仍过。真机靶场能一口气托管跑完一条 >10 步的只读链、遇档 2 停。

## 一句话

托管到位,是"你说一声、确认一次,它自己跑到该停的地方才停,全程你看得见、随时能喊停" ——
