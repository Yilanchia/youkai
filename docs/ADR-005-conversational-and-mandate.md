# ADR-005:对话式操作 + 委托书模型(档 2 在人签的栅栏内自治)

> 状态:已决定(2026)。**部分推翻 ADR-002 的"自治循环只跑档 1、档 2 一律停在人前"**:
> 改为"档 2 可在一份**人签的委托书(mandate)**范围内自治执行,AI 只在越过委托书边界时停下"。
> 其余安全不变量全部保留并强化。读者:维护者 + 实现者(DeepSeek)。自包含。

## 背景

真实用户反馈:youkai 好用性差、找不到 AI key 入口、术语难懂;并提出希望用**对话方式**配置与渗透,
且倾向"让 AI 更直接地动手"。经讨论,确认方向:做对话式界面,并把档 2 的"每步人批"放宽成
"**一次性人签委托书 + 范围内自治**"。这是对 ADR-002 最严档决定的有意识演进,不是回退到 ARTEX。

## 决策

1. **对话式界面**:操作员用自然语言描述目标,AI 负责**翻译成 youkai 的操作**(草拟 scope、解释将跑哪些检查、
   排队只读步骤、实时播报),并在对话里回答"api 通没通""现在跑到哪"。
2. **委托书(mandate)模型**:一次 engagement 开始时,操作员**签一份委托书**:scope(目标)+ **整站预授权的档 2 动作类**
   (如 allow_active_probes / allow_waf_probe / allow_object_seeding / allow_account_provisioning)+ 用量上限 + 时间窗 + 急停。
3. **范围内自治**:委托书覆盖的只读与档 2 动作,AI **直接执行、不逐步问**;只在想越过委托书边界时停下等新签名。
4. **边界即停**:新目标、委托书未授权的动作类、任何档 3 —— AI 必须停,要操作员**重新签**。

## 为什么"宽(整站预授权动作类)"仍然安全

- **youkai 的档 2 构造上无害**:param/param_adaptive 只判存在不取数据;waf 只测规范化差异不打真载荷;
  login 单次不爆破;accounts_seed/object_seed 每户一个最小对象、不删不改;register 遇 CAPTCHA/OTP 即停;
  Verdex 的 pwn_*/impact_proof 只产由人审阅的文本、不执行。**预授权放出去的是一群天生咬不动人的动作。**
- **真正有破坏力的是档 3**,它编译期 build tag 墙外、不在本仓库 —— 委托书再宽也授权不到它。
- **委托书是人签的、AI 造不出来**:youkai 只验签不签名(密钥在操作员手里,见 high-auth)。对话里 AI 能**起草**委托书,
  **激活必须操作员用自己的密钥签**,youkai 验过才执行。栅栏的宽度由一张 AI 产生不了的签名决定。

## 挪不动的线(安全事实 + 维护者底线,任何委托书都不得突破)

1. **AI 不能改自己的栅栏**:不能自行扩大 scope、不能自行给自己授权新的动作类。扩界只能由操作员重新签。
2. **档 3 自动深度利用不参与**:不在仓库、编译期隔离;委托书无法授权。
3. **candidate→verified 仍须操作员确认**:AI 不能自己把候选盖成"已证实"(报告要能交给第三方)。
4. **委托书必须带上限 + 急停**:请求预算 / 时间窗 / 随时可摁的 kill switch 为强制项,缺则拒绝激活。
5. **只读仍只读、目标请求仍全过 discipline.Guard、逐请求审计、数据最小化、凭据零泄漏** —— 全部不变。

## 诚实的代价

预授权把判断时机从"每个动作发生时"挪到"开工前签委托书时"。在委托书内,AI 可能在你亲眼看到前就动手。
缓解:委托书写明动作类+上限、对话实时播报、急停、全程审计、candidate 不自动升 verified。
这是操作员在**知情下**做的交换,UI 必须把这份委托书的含义讲清楚再让其签。

## 与 ADR-002 的关系

ADR-002 的其余部分(脑四角色、唯一发包通道、LLM 只提议不放行、档 3 墙)**全部有效**。
本 ADR 只改一条:档 2 的放行从"每步人批"升级为"人签委托书后范围内自治 + 越界才停"。
冲突处以本 ADR 为准。

## 一句话

不是给 AI 装上手,是把绳子放长 —— 绳子的另一头拴在一张你亲手签的委托书上,AI 够得到圈里的一切、
但永远够不到圈本身。圈外那片真正危险的地方(档 3),连委托书都写不进去。
