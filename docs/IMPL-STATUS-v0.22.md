# IMPL-STATUS v0.22 — harness 托管:一个窗口、自己跑到真停止点

> 日期:2026-11-16 · 承接 DEVPLAN-v0.22 · `go test ./...` 全绿 · 浏览器里点的
> **纯体验/托管**:没有新增能力,一道闸都没动。

## 一句话

以前确认开工之后,跑满十步就停,要你再去点一次;对话和步骤流还是两块面板。
现在**一个窗口、一条时间线**,它自己跑到底,只在该你拍板的地方停下,并且停的时候会说话。

## 模块一 · 托管自动续跑(核心)

`startRun` 的后台 goroutine 从"跑一轮"变成**监督循环**:

| 停止原因 | 归类 | 行为 |
|---|---|---|
| `max_steps`(单轮上限) | **假停** | 自动开下一轮,并播一条"继续托管…" |
| `needs_approval` | **真停** | 停,等你点头 |
| `sensitive` | **真停** | 停,交人复核 |
| `idle` | **真停** | 停,给小结 |
| `cancelled` | **真停** | 停(你喊的) |
| 预算到顶(默认 50 步) | **真停** | 停,说明"想再跑就再来一程" |

- 预算:`-`(默认 50),`s.cfg.SuperviseBudget` 可覆盖;
- **「停下」按钮**:`POST /api/engagements/{id}/runs/{runID}/cancel`,取消整场托管而不只是当前一轮;
- 每一步仍然走同一套闸,档 2 仍然逐个 park。

### 实现时踩到并修掉的一个真 bug

引擎在**每一轮结束时都会写 run 行**(`FinishRun`)。托管一开多轮,第一轮跑满 10 步就把
run 标成 `max_steps` 完结 —— 界面和测试都会以为"它跑完了",而实际上循环还在继续。

修:`engine.Config.NoFinishRun`,托管时由**监督层**独占 run 生命周期,只在真正结束时写一次。
（这个问题在单轮的旧代码里看不出来,是托管把它照出来的。）

## 模块二 · 一条时间线

`web/timeline.js`(新):把对话气泡和步骤行**按时间合并成一条滚动记录**。

实测(浏览器):

```
你     帮我测一下这个站
youkai 我还没有接上模型,所以只能给你指路…(指路卡)
       说明:没有 AI 时,只读检查依然会跑…
＋     从账本推出 3 个新步骤
▸      扫描   http://127.0.0.1:18080        tier1  得到 7 条事实、6 条候选
▸      读 API 文档 …/openapi.json            tier1  得到 6 条事实、1 条候选
▸      探测   …/.git/config                  tier1  得到 2 条事实
■      结束:这一轮没有可做的新步骤了
youkai 这一程只读检查跑完了:10 次请求、7 条候选发现(已确认 0 —— candidate 不等于 verified)…
```

顶部是 harness 活动条:`● 托管中(第 N 步)… / 停在 N 个动作前,等你拍板 / 已达本次托管预算`,
运行中旁边就是「停下」。

### 时间线的两个坑

1. **时间戳格式**:`to_char(..., OF)` 给的是 `+08`(没有分钟),JS `Date.parse` 直接 NaN →
   消息排序跑到最上面。改成 UTC + 毫秒(`...SS.US || 'Z'`),前端 `parseTime` 再兜一层。
2. **没有 AI 时你说的话会丢**:v0.20 的无模型分支只回话、不落库,刷新就没了。
   现在把用户消息和回复都写进历史 —— 对话是记录,不是临时提示。

## 模块三 · 停下时的小结

监督层在**真正停下**时写一条 assistant 消息(模板,不依赖模型):

- 档 2:「我先停在这里:有动作需要你拍板…到目前为止 X 次请求、Y 条候选发现。批了我接着跑。」
- idle:「这一程只读检查跑完了:X 次请求、Y 条候选发现(已确认 0 —— candidate 不等于 verified)。接下来可以:看结果 / 继续深挖 / 换目标。」
- 预算:「这一程的托管预算用完了(50 步)…还想继续就再点一次「开始扫描」。」
- 敏感:「遇到了疑似敏感数据,我不会继续读,也不会写进报告正文 —— 请人工确认。」

写作时机在 `FinishRun` **之前**,否则界面会先看到"已结束"、再等消息出现(测试抓到了这个竞态)。

## 验收

```
api  TestSupervisedRunCrossesTheStepCapItself   15 步任务、单轮上限 10 → 一个 run 跑完 15 步,status=idle
     TestSupervisedRunStopsAtATierTwoStep        同样的循环绝不跨过档 2:status=needs_approval,param 仍 needs_approval
     TestCancelStopsASupervisedRun               「停下」即时生效,40 步的活只跑了 5 步
     TestSupervisedRunEndsWithATurn              结束时有一句人话小结,且不声称自己做过未授权的事
真机  时间线:你→AI→步骤→小结 一条线;刷新还在;无 AI 时你说的话也留得住
```

## 没做的(如实)

- **托管预算不按请求数计**:用步数(默认 50),`max_requests` 仍由护照在 Guard 层硬顶,两者没合并成一个数。
- **「继续托管」按钮**没有单独做:预算到顶后再点一次「开始扫描」即可,语义相同。
- **小结是模板**:有 LLM 时没有让它改写得更自然(模板胜在稳定、可测、不撒谎)。
- 时间线**按时间排序**,同一毫秒内的消息与步骤用固定次序(消息在前);没有做"因果缩进"。

## 一句话

托管到位:**确认一次,它自己跑到该停的地方;全程一条线,随时能喊停**。
自主体现在"不用每十步催一次",放心体现在"它绝不自己跨过那条该你拍板的线"。
