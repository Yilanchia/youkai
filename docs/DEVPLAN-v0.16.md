# DEVPLAN-v0.16:逆向深度 + 反致盲 — 看穿 bla 这类 AI-逆向对抗,照样把授权样本分析穿

> 交付对象:实现者(DeepSeek)。配 ADR-004(吸收 Verdex)、ADR-006(点头批准)、v0.13(数据流假设)读。
> 目标:两件事 ——(1) 把二进制逆向做深:更多架构、漏洞模式识别、source→sink 数据流链(web 白盒的二进制版);
> (2) **反致盲**:识别并抵抗 bla 这类"致盲 AI 逆向"的保护(投毒/幻觉诱导/反调试/混淆),不被假数据带偏,尽力还原真实结构。
> 全程只读静态分析、本地、不执行样本。**针对的是技术保护这道墙,不是任何人;不 hack-back、不反制部署方。**

## 0. 背景(为什么做反致盲)

[qybaihe/bla](https://github.com/qybaihe/bla) 是防御型工具,用"投毒→耗尽→幻觉"在二进制层面**致盲 LLM 逆向 agent**:喂假符号、
制造海量噪声耗尽上下文、诱导模型产出错误结论。youkai 作为只读取证脑,面对一个**被授权分析但被 bla 处理过的样本**,
现在会被带偏。本轮让 youkai:**认出"这被致盲处理过"→ 不轻信表面数据 → 用结构性事实而非模型臆测下结论**。
这对称正当:bla 保护"你拥有的软件",youkai 分析"你被授权的样本"——都在授权内。

## 0.5 不可动摇(本轮红线)

- **只读静态、本地、不执行样本**:所有分析不运行目标、不联网、不脱壳执行;沿用 Verdex 只读纪律。
- **不 hack-back / 不反制**:反致盲是"看穿保护继续分析",**不是**攻击 bla 作者/部署方/任何机器。对抗的是数据,不是人。
- **诚实优先,不臆造**:被致盲且无法确证时,**如实标"分析受对抗干扰,结论不可靠"**,绝不为了"还击"硬给一个假结论——那正好中了 bla 的"幻觉"圈套。
- **授权前提**:样本仍需 handoff 登记 + 在授权范围;反致盲不改变"只分析授权样本"。
- 逆向产出的危险点(可利用性)仍是**候选/假设**,利用仍只产人工审阅的文本(Verdex pwn_* 档 2),不自动利用。

## 1. 反致盲识别 `internal/binary/antiblind.go`(P0,最针对"不甘心")

**目标**:识别样本是否被 AI-逆向对抗处理过,给分析加一个"可信度"维度,防止 youkai 把投毒数据当真。

**识别信号(只读,基于结构统计)**:
- **投毒符号/字符串**:异常密集的"看似有意义但矛盾"的符号名、重复诱导串、与实际代码不匹配的假元数据。
- **噪声耗尽**:超大无意义节区、海量重复函数/字符串(目的是撑爆模型上下文)——统计熵 + 重复率识别。
- **反调试/反分析标志**:常见 anti-debug API/指令序列(ptrace、IsDebuggerPresent、时间检查、int3 扫描等)——只标记存在,不绕过执行。
- **混淆特征**:控制流平坦化、字符串加密、packer 壳头(UPX 等)——识别并标注,给出"需脱壳/需动态(人工)"提示。

**产出**:`fact(kind=anti-analysis, signal=<poison|noise|anti-debug|obfuscation|packer>, confidence, note)` + 一个样本级
**可信度标记**(clean / suspected-blinded / heavily-blinded)。下游分析据此降权表面数据。

**实现要点**:纯结构统计 + 特征匹配,不执行样本;识别到 packer 就明说"壳下真实代码需人工脱壳后再 handoff",不自动脱壳执行。

**验收**:对一个 bla 处理过的样本 → 标 suspected/heavily-blinded 且列出命中信号;干净样本 → clean;识别 packer 给人工提示;全程不执行样本。

## 2. 抗干扰分析:信结构,不信表面 `internal/binary/*.go`(P0)

**目标**:在反致盲标记下,分析改用**不易被投毒的结构性证据**,少依赖易被污染的符号/字符串。

**要点**:
- 被标 blinded 的样本:符号名/字符串**降权**(标"可能投毒,仅参考"),优先用**调用图/控制流/交叉引用/常量/系统调用序列**这类结构事实下结论。
- secrets/dataflow 等现有分析:命中项都附"在对抗样本中可信度降低"的 counter,交人复核。
- **宁可少报不可假报**:无法穿透的部分如实标"受对抗保护,未能确证",不猜。

**验收**:blinded 样本里,结论优先引用结构证据;表面符号命中都带降权 counter;不可确证处如实标注,不产假结论。

## 3. 二进制 source→sink 数据流 `internal/binary/binflow.go`(P1,web 白盒的二进制版)

**目标**:把 v0.13 web 白盒的"source→sink 假设"搬到二进制:输入点(argv/网络读/文件读)追到危险函数(system/exec/strcpy/memcpy/格式化串),产**假设**。

**要点**:
- source:命令行参数、`recv`/`read`、文件读取、环境变量。
- sink:`system`/`exec*`/`popen`(命令执行)、`strcpy`/`sprintf`/`memcpy`(内存破坏)、格式化串、反序列化。
- 产 `hypothesis(code-only)`,**和 web 一样:只是线索,不是发现**;可利用性需人工在授权下验证(Verdex pwn_* 档 2 产文本)。
- 被致盲样本的假设附"结构推断,表面数据可能投毒"。

**验收**:构造 argv→system 的样本 → 产命令执行假设(code-only);strcpy 无边界 → 内存破坏假设;假设不自动升发现;blinded 样本假设带可信度注记。

## 4. 架构 / 格式覆盖扩展(P2)

**目标**:补 Verdex 现有覆盖的短板架构/格式(按实现成本排:先 ARM/ARM64、再 MIPS;WASM 深度;.NET/Java 字节码的数据流)。

**要点**:复用 Verdex 后端(objdump/反编译器),缺后端如实降级(doctor 预检),不伪造。

**验收**:ARM64 样本能出符号/反汇编/数据流;缺后端标红降级不崩。

## 5. 报告 / 对话(P2)

- 报告里二进制发现标注可信度(是否来自对抗样本);反致盲信号单列一节。
- 对话里 AI 可说"这个样本看起来被 bla 投毒了,表面符号不可信,我按调用图分析"——仍是分析陈述,利用仍交人。

## 落地顺序

1. 模块一(反致盲识别)—— 最针对诉求,先做。
2. 模块二(抗干扰分析:信结构不信表面)。
3. 模块三(二进制数据流假设)。
4. 模块四/五(架构扩展 + 报告)。

**每步验收锚点**:只读不执行样本;反致盲只识别不绕过执行、packer 交人脱壳;被致盲处如实标不可靠、绝不假报;
二进制假设≠发现、利用只产文本;不 hack-back;`go test ./...` 全绿。

## 一句话

bla 想让 AI 逆向"看花眼",youkai 的还击不是打回去,是**认出它在撒谎、然后信结构不信谎言,把真东西挖出来** ——
挖不穿的地方老实说挖不穿,绝不被诱导着编一个假结论,因为编假结论恰恰就输给了它。
